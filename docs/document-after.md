# AI 水印去除客户端工具落地方案



> 目标：针对豆包、千问等 AI 生成图片的右下角半透明水印，构建本地桌面客户端。默认采用 **逆 Alpha / 逆混合数学还原** 主路径，图像修复模型仅作为异常回退。输出结果在水印区域及过渡带达到像素级近似，肉眼难以分辨，并附带可验证的 PSNR / SSIM / 最大像素差报告。  

> 合规前提：仅处理用户自己生成或拥有合法处理权的图片，不面向去除第三方版权内容水印。



---



## 1. 项目目标与边界



### 1.1 核心目标



| 目标 | 可量化标准 |

|---|---|

| 像素级还原 | 水印区域及外扩 2~4 px 过渡带：PSNR > 50 dB、SSIM > 0.999、逐通道最大绝对像素差 ≤ 2 |

| 非水印区域零改动 | 水印边界框外像素逐字节一致 |

| 本地离线 | 图片不上传，核心运算与模型推理均在客户端完成 |

| 可扩展 | 新增水印模板无需改核心代码，通过模板注册表热更新 |

| 可验证 | 每张输出图生成验证报告，未达标自动标记 |



### 1.2 非目标



- 不做通用“任意水印”一键去除；未知水印仅提供保守回退与手动蒙版。

- 不以生成式修复作为默认路径；LaMa 等模型只处理逆混合失败区域。

- 不承诺对重度压缩、二次截图、水印位置被裁剪的图片达到像素级还原。

## 4. 核心模块设计



### 4.1 水印模板注册表 `watermark-registry`



每个品牌水印对应一个模板 JSON，包含定位规则、Alpha 贴图、颜色、混合模式。



```json

{

  "id": "doubao_v1",

  "displayName": "豆包 AI 水印 v1",

  "version": 1,

  "blendMode": "screen",

  "color": [255, 255, 255],

  "anchor": "bottom-right",

  "bboxRule": {

    "type": "relative",

    "x": -0.22,

    "y": -0.12,

    "w": 0.18,

    "h": 0.08,

    "minPx": 48,

    "paddingPx": 4

  },

  "alphaMap": "alpha_maps/doubao_v1.png",

  "alphaScaleMode": "stretch-to-bbox",

  "minImageSize": [256, 256],

  "notes": "需用纯黑/纯白样本联合标定抗锯齿边缘"

}

```



**规则：**

- `bboxRule` 支持相对坐标与最小像素保护；

- `alphaMap` 为灰度 PNG，值 0~255 映射 α∈[0,1]；

- 模板带版本号，客户端启动时校验完整性；支持远程/手动导入更新；

- 同一品牌可有多个变体模板，按图片尺寸和置信度选择。



### 4.2 定位模块 `locator`



处理顺序：



1. **模板精确匹配**：按 `bboxRule` 计算候选框，与 Alpha 贴图做归一化互相关，置信度 ≥ 0.85 视为命中。

2. **右下角启发式搜索**：在右下 30% 区域内搜索低对比度水平文字/图标连通域，生成候选框，置信度低时要求用户确认。

3. **手动框选**：UI 提供手动蒙版，走回退修复路径。



输出结构：



```rust

struct LocatedWatermark {

    template_id: Option<String>,

    bbox: Rect,          // 像素坐标

    confidence: f32,

    alpha_map: Option<AlphaMap>,

}

```



### 4.3 逆混合引擎 `reverse-alpha`



#### 标准 Alpha 混合逆运算



对每个通道：



\[

C_{out} = \alpha \cdot C_{wm} + (1-\alpha)\cdot C_{src}

\]



\[

C_{src} = \frac{C_{out} - \alpha \cdot C_{wm}}{1-\alpha},\quad \alpha < 1

\]



#### Screen 混合逆运算



Screen 正向：



\[

C_{out} = 1 - (1-C_{src})(1-\alpha C_{wm})

\]



逆运算需单独推导并做单元测试。实现上按模板 `blendMode` 分派，**禁止复用 Alpha 公式处理 Screen 模式**。



#### 工程要点



- 全部在 `f32` 域计算，最后按 **四舍五入** 回 0~255，避免截断引入系统性偏暗；

- `α ≥ 0.999` 的像素标记为不可逆，交由回退引擎；

- 输出后对 bbox 外区域做逐字节一致性校验；

- 对 bbox 边缘外扩 `paddingPx` 做过渡带验证。



伪代码：



```rust


fn reverse_alpha_block(

    src: &[u8], alpha: &[f32], color: [f32;3], mode: BlendMode, out: &mut [u8]

) -> Result<(), PixelError> {

    for i in 0..alpha.len() {

        let a = alpha[i];

        if a >= 0.999 { return Err(PixelError::Irreversible(i)); }

        for c in 0..3 {

            let blended = src[i*3+c] as f32 / 255.0;

            let wm = color[c];

            let original = match mode {

                BlendMode::Alpha => (blended - a * wm) / (1.0 - a),

                BlendMode::Screen => screen_inverse(blended, a, wm),

            };

            out[i*3+c] = (original.clamp(0.0,1.0) * 255.0).round() as u8;

        }

    }

    Ok(())

}

```



### 4.4 回退修复 `fallback-inpaint`



- 模型：LaMa ONNX（FP32 优先，可选 INT8）；

- 触发条件：模板未命中、`α≥0.999` 像素比例超阈值、逆混合验证不达标；

- 掩码策略：仅覆盖水印 Alpha > 0 的像素并外扩 2 px，**尽量紧**，避免大范围重建；

- 模型懒加载，首次使用时加载，闲置 5 分钟释放内存；

- 回退结果单独标记，报告中注明“非数学还原”。



### 4.5 验证模块 `validator`



在水印 bbox 及外扩 2~4 px 过渡带上计算：



| 指标 | 通过阈值 | 说明 |

|---|---|---|

| PSNR | > 50 dB | 逆混合理想情况下远高于此 |

| SSIM | > 0.999 | 结构一致性 |

| MaxAbsDiff | ≤ 2 | 逐通道最大绝对差 |

| bbox 外一致性 | 0 差异 | 逐字节比较 |



验证不通过时：

- 输出仍可保存，但标记 `needs_review`；

- UI 高亮问题区域，提供“切换回退修复”按钮；

- 批量模式下生成汇总报告 CSV/JSON。

## 5. 水印模板标定流程



这是像素级还原的关键前置工作，需作为独立阶段完成。



### 5.1 标定步骤



1. **样本采集**：每个品牌至少采集 10 张纯黑背景、10 张纯白背景、20 张真实生成图，覆盖不同分辨率与压缩质量。

2. **Alpha 估计**：在纯黑/纯白样本上联合求解每个像素的 α 与前景色，抑制单张样本噪声。

3. **边缘处理**：对抗锯齿边缘做亚像素对齐，记录 `alphaMap` 的缩放规则。

4. **混合模式确认**：用已知前景色与 α 对真实图做正向混合，与平台输出比对，确认 Screen / Alpha 模式及参数。

5. **回归验证**：用标定结果对留出样本做逆混合，统计 PSNR/SSIM/MaxAbsDiff，达标后发布模板。

6. **版本化**：模板与 Alpha 图带版本号；平台更新水印后重新走流程。



### 5.2 标定工具



在 `templates-src/` 下提供 CLI 工具：

- `calibrate alpha --black ... --white ... --out alpha.png`

- `verify-template --template doubao_v1 --samples ./samples`

- 输出标定报告与建议阈值。

## 6. UI 与交互设计



### 6.1 核心界面



- **单张模式**：拖拽导入 → 自动识别模板 → 预览原图/结果对比 → 像素探针 → 保存。

- **批量模式**：文件夹导入 → 队列处理 → 每张显示验证状态（通过/需复核/失败）→ 批量导出 + 汇总报告。

- **对比查看器**：左右分屏、按住空格切换原图、放大镜、像素 RGB/α 值探针。

- **报告面板**：显示模板 ID、PSNR、SSIM、MaxAbsDiff、是否回退、不可逆像素数。

- **设置**：模板管理、模型路径、输出格式（PNG 无损优先）、是否保留 EXIF。



### 6.2 输出策略



- 默认输出 **PNG 无损**，避免二次 JPEG 压缩破坏像素级验证；

- 若输入为 JPEG，可选输出 PNG 或高质量 JPEG（报告中注明有损）；

- 非水印区域不做任何重编码改动（解码后逐字节保持）。

## 7. 测试与验收计划



### 7.1 测试分层



| 层级 | 内容 |

|---|---|

| 单元测试 | Screen 逆运算正向/逆向互逆性；α=0、α→1、舍入边界；bbox 计算 |

| 标定回归 | 每个模板对留出样本的 PSNR/SSIM/MaxAbsDiff 分布 |

| 集成测试 | 导入→定位→逆混合→验证→导出全链路 |

| 像素一致性 | 非水印区域逐字节比对 |

| 性能测试 | 4000×3000 图片单张处理时间、批量 100 张内存峰值 |

| 兼容性 | Windows 10/11、macOS 13+、Linux AppImage |

| 异常测试 | 无水印图、裁剪水印、二次截图、非标准位置 |



### 7.2 验收标准（MVP）



- [ ] 豆包、千问各至少 1 个模板通过标定回归，留出样本 95% 以上达到 PSNR>50 dB、SSIM>0.999、MaxAbsDiff≤2；

- [ ] 非水印区域逐字节零差异；

- [ ] 单张 4K 图片处理时间 < 2 秒（不含模型加载）；

- [ ] 批量 100 张无内存泄漏，峰值内存 < 1.5 GB（不含 ONNX 模型）；

- [ ] 所有输出附带验证报告；未达标图明确标记；

- [ ] 安装包 Windows < 30 MB（不含可选模型），模型按需下载/导入；

- [ ] 合规提示在首次启动与导出时展示。

## 9. 风险与应对



| 风险 | 影响 | 应对 |

|---|---|---|

| Alpha 标定误差导致边缘伪影 | 像素级不达标 | 纯黑/纯白联合估计；抗锯齿亚像素对齐；回归门禁 |

| Screen 逆运算推导错误 | 系统性色偏 | 正向/逆向互逆性单元测试；真实样本比对 |

| 平台更新水印样式 | 模板失效 | 模板版本化、置信度门禁、快速重标定流程 |

| 8-bit 舍入产生色阶 | 局部 MaxAbsDiff 超阈 | 四舍五入而非截断；f32 中间计算；问题像素标记 |

| LaMa 回退结果不精确 | 用户误以为像素级 | 报告中明确标注“非数学还原”；UI 区分状态 |

| 模型体积与内存 | 安装包大、低配卡顿 | 模型可选下载；懒加载；INT8 可选 |

| 合规风险 | 法律与平台条款 | 首次启动合规提示；仅限自有图片；不提供第三方版权内容去除引导 |

## 11. 关键结论



本方案的落地关键是**把“去水印”拆成“可数学逆运算的已知叠加”与“不可逆时的保守修复”两类问题**。豆包、千问的水印形态允许前者，因此默认路径必须是逆 Alpha / 逆 Screen 混合，而不是生成式修复。用 PSNR、SSIM、MaxAbsDiff 和 bbox 外逐字节一致性作为硬门禁，才能把“肉眼很难分辨”转化为可验收的工程指标。LaMa 仅作为异常回退，并在报告中明确标注，避免混淆像素级还原与视觉修复。
